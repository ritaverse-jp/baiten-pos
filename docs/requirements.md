## 1. プロジェクト概要

### 1.1 背景

売店における商品の注文受付・会計処理を、手書き伝票や電卓に依存して運用している。集計作業が締め作業時に発生し、記入ミス・計算ミス・転記漏れが起こりやすい状態にある。

### 1.2 目的

- 手持ちのスマートフォン／タブレットのみで注文入力から精算までを完結させる
- 会計データを自動でスプレッドシートへ蓄積し、売上集計の手作業をなくす
- 専用レジ機器・レシートプリンタ等の初期投資を伴わない構成とする
- 専用データベースを設けず、Google スプレッドシートを唯一のデータ保管先（正データ）とし、月額のサーバー費用を発生させない構成とする

### 1.3 ゴール（達成指標）

| 指標 | 現状 | 目標 |
| --- | --- | --- |
| 1会計あたりの入力時間 | － | 30秒以内 |
| 締め作業（日次集計）の所要時間 | － | 0分（自動集計） |
| 計算・転記ミス | 発生 | 0件 |

## 2. スコープ

### 2.1 対象範囲（本開発に含む）

- 商品マスタ管理（登録・編集・削除）
- カテゴリマスタ管理（登録・編集・削除、商品の振り分け）
- 注文入力（伝票作成・商品追加・個数変更・割引適用）
- 精算処理（合計金額算出・預かり金入力・釣銭算出）
- 会計確定時のスプレッドシートへの自動転記

### 2.2 対象外（本開発に含まない）

- キャッシュレス決済（クレジットカード・QRコード決済等）との連携
- レシート・領収書の印刷（プリンタ連携）
- 在庫管理・発注管理
- 従業員のシフト管理、勤怠管理
- 会計ソフト（freee 等）との直接連携
- 顧客管理・ポイント管理

> 対象外の項目は将来的な拡張候補として「10. 将来拡張の想定」に記載する。

## 4. 利用者・利用シーン

### 4.1 利用者区分

| 区分 | 想定人数 | 主な操作 |
| --- | --- | --- |
| 店舗スタッフ（会計担当） | 1〜数名 | 注文入力・精算 |
| 管理者（店舗責任者） | 1名 | 商品／カテゴリのマスタ管理、売上確認 |

> 権限を分離するかどうかは「11. 確認事項」に記載。初版は全員が全機能を利用できる想定とする。

### 4.2 業務フロー（会計時）

```
1. 客が商品を持ってレジに来る
        ↓
2. スタッフが商品のNo.（①②…）を入力 → 伝票に商品行が追加される
        ↓
3. 同じ商品が複数ある場合は個数を変更（または同じNo.を連続入力）
        ↓
4. 必要に応じて商品ごとに円単位の割引を入力
        ↓
5. 合計金額を客に伝える
        ↓
6. 預かり金を入力 → 釣銭が自動表示される
        ↓
7. 「会計確定」を押す → スプレッドシートへ自動転記、伝票がクリアされる
```

## 5. システム構成

### 5.1 方式

| 項目 | 内容 |
| --- | --- |
| 提供形態 | Web アプリケーション（PWA：ホーム画面に追加してアプリのように利用） |
| 対応端末 | iOS / iPadOS / Android のスマートフォン・タブレット（**複数台での同時利用に対応**） |
| 対応ブラウザ | Safari（最新版）、Google Chrome（最新版） |
| 画面向き | 縦・横の両方に対応（タブレットは横向きを推奨） |
| データ保存先 | Google スプレッドシートを唯一の正データとする（商品・カテゴリ・売上・端末の各タブ）。端末側は IndexedDB にマスタと未送信売上をキャッシュするのみ |
| バックエンド | Google Apps Script（GAS）を Web アプリとして公開し、スプレッドシートへの読み書きを担う。専用サーバー・専用DBは設けない |

### 5.2 採用構成【確定】

専用データベースは設けず、**Google スプレッドシートを唯一のデータ保管先**とする。月額のサーバー・DB費用を発生させないことを構成上の要件とする。

| 層 | 採用技術 | 役割 |
| --- | --- | --- |
| データストア | Google スプレッドシート | 商品マスタ・カテゴリ・売上ログ・端末情報をタブ単位で保持する唯一の正データ |
| バックエンド | Google Apps Script（GAS）の Web アプリ | スプレッドシートへの読み書きを行う API。マスタ取得・売上一括追記・端末登録のエンドポイントを提供 |
| フロントエンド | PWA（Vite + React + TypeScript） | 端末上の画面。Service Worker でオフライン起動、IndexedDB にマスタと未送信売上をキャッシュ |

**DBを持たない構成で複数台・オフライン要件を満たす設計上の要点**

- **会計番号に端末コードを含める**ため、連番を中央で管理する必要がない。各端末が独立して採番でき、複数台が同時にオフラインでも番号が衝突しない（5.4）
- **売上ログは追記専用**とし、GAS の `LockService` で書き込みを直列化することで、複数台からの同時追記でも競合しない
- **マスタは端末側 IndexedDB にキャッシュ**して参照するため、会計操作はネットワーク応答を待たない。GAS の応答速度が会計体験に影響しない

**フロントエンドを GAS 上に載せない理由**

GAS の HTML Service でフロントを配信する方式もあるが、Service Worker を用いたオフライン PWA との相性が悪い。したがってフロントは独立した静的 PWA として配信し、GAS はデータ API に徹する構成とする。

**制約（許容事項）**

GAS の Web アプリは1回の呼び出しに数百ミリ秒を要し、1日あたりの実行回数・実行時間に Google の割当上限がある。売店規模の会計頻度では問題とならないが、極端に高頻度・大量の会計には不向きである点を前提とする。

### 5.3 スプレッドシート連携

- 会計確定時、フロントは売上明細を GAS のエンドポイントへ送信し、GAS が売上ログのタブ末尾に行を追記する
- 送信は非同期で行い、失敗時は端末内の未送信キューに保留して自動リトライする（通信断時も会計を止めない）
- 同時追記の競合を防ぐため、GAS 側の追記処理は `LockService` で直列化する
- スプレッドシート側の手作業による編集は、集計の正確性を損なうため原則行わない運用とする

### 5.4 複数台運用要件【確定】

繁忙時のレジ増設を想定し、複数台の端末で同時に会計を行える構成とする。

| 項目 | 要件 |
| --- | --- |
| 台数 | 同一店舗で複数台の端末を同時に利用できる |
| マスタ共有 | 商品・カテゴリのマスタはスプレッドシート上で一元管理し、全端末で共有する。1台で編集した内容はスプレッドシートに反映され、他端末はオンライン時に再取得して同期する |
| 端末登録 | 各端末に固有の端末識別子（端末コード：A・B・C… または任意名称）を割り当てる。初回利用時に登録する |
| 会計番号 | 会計番号に端末識別子を含め、端末をまたいでも重複しない採番とする（9.1・下記参照） |
| 伝票の独立 | 入力中の伝票は各端末で独立して保持する。他端末の入力中伝票は共有しない |
| 履歴の統合 | 会計履歴および売上集計は、全端末分をスプレッドシート上で統合して確認できる |
| マスタ編集の競合 | マスタ編集はオンライン時のみ可能とし、同一項目の同時編集は「後勝ち」で処理する。編集操作はログに記録する |

**会計番号の採番規則（複数台対応・確定）**

```
形式：YYYYMMDD-{端末コード}{連番3桁}
例  ：20260723-A014（A端末の当日14件目）
     　20260723-B003（B端末の当日3件目）
```

- 連番は端末ごと・日付ごとに 001 から採番する
- 端末コードを含めることで、各端末がオフラインで採番しても会計番号が全体で一意になる
- スプレッドシート上では端末コードで絞り込むことで、端末別の売上も確認できる

### 6.2 FR-01 商品マスタ管理

**登録項目**

| 項目 | 型 | 必須 | 備考 |
| --- | --- | --- | --- |
| No. | 数値 | ○ | 画面上は①②③…の丸数字で表示。重複不可 |
| 商品名 | 文字列（30文字以内） | ○ | |
| 金額 | 整数（円・税込） | ○ | 0円以上 |
| カテゴリ | 選択 | ○ | FR-02 で登録したカテゴリから選択 |
| 表示順 | 数値 | － | 未指定時は No. 順 |
| 販売状態 | 有効／無効 | ○ | 無効にすると会計画面に表示されない（削除せず一時的に非表示にする用途） |

**要件**

- No. は1〜99の範囲とし、丸数字（①〜⑳）で表示する。21以降は通常数字で表示する
- 既存の No. と重複する登録・編集はエラーとする
- 削除時は確認ダイアログを表示する。過去の会計履歴に影響を与えない（履歴は登録時点の商品名・金額を保持する）
- 金額の変更は、変更後の会計から適用される（過去の会計は遡って変更されない）

### 6.3 FR-02 カテゴリマスタ管理

**登録項目**

| 項目 | 型 | 必須 | 備考 |
| --- | --- | --- | --- |
| カテゴリ名 | 文字列（20文字以内） | ○ | 重複不可 |
| 表示順 | 数値 | － | 会計画面のタブ並び順 |
| 表示色 | 選択 | － | 視認性向上のため任意で設定 |

**要件**

- カテゴリは会計画面のタブ（またはボタン群）として表示され、選択すると該当カテゴリの商品のみが一覧表示される
- 商品が1件以上紐づくカテゴリは削除できない（先に商品の移動または削除が必要）。削除時はその旨を通知する
- 商品編集画面からカテゴリを変更することで振り分けを行う

### 6.4 FR-03 No. 入力による商品追加

- 会計画面にテンキーを常時表示し、No. を入力して「追加」で伝票に商品行が追加される
- 存在しない No. が入力された場合はエラーメッセージを表示し、伝票は変更しない
- すでに伝票に存在する商品と同じ No. を追加した場合は、**既存行の個数を +1 する**（新規行を作らない）
- 割引が適用済みの行に同一 No. を追加した場合も、既存行の個数を +1 する。割引は商品単体に対する設定であるため、追加された1点にも同じ割引が適用される
- 同一商品で異なる割引を設定したい場合は、伝票行の「行を分ける」操作により別行として扱えるものとする

### 6.5 FR-05 個数変更

- 伝票の各行に「−」「＋」ボタンを配置し、タップで個数を増減できる
- 個数の直接入力も可能とする（1〜99）
- 個数を 0 にした場合は行を削除する（確認ダイアログを表示）

### 6.6 FR-07 円割引【確定】

- 伝票の各行に対して、円単位の割引額を入力できる
- 割引は**商品単体（1点あたりの単価）に対して適用**する
  - 例：単価500円・個数2・割引50円 → （500 − 50）× 2 ＝ **900円**
- 割引額は 0円以上、かつ単価以下とする。単価を超える入力はエラーとする
- 割引が適用された行は、金額の横に割引額を明示表示する（例：`500 − 50`）
- 割引は伝票内の行単位で個別に設定でき、同一商品でも別行に分けて異なる割引を設定できる（6.4 参照）

### 6.7 計算仕様

```
行小計   = （商品単価 − 行割引額）× 個数
合計金額 = 全行の行小計の総和
釣銭     = 預かり金 − 合計金額
```

- すべて整数円で計算する（小数は発生しない）
- 預かり金が合計金額未満の場合、釣銭欄に不足額を赤字で表示し、会計確定ボタンを非活性にする

### 6.8 FR-09／FR-10 預かり金・釣銭

- テンキーによる直接入力に加え、よく使う金額のクイックボタンを配置する（1,000円／5,000円／10,000円／ちょうど）
- 釣銭は入力と同時にリアルタイムで大きく表示する（読み上げ・受け渡しのため視認性を最優先）

### 6.9 FR-11 会計確定・スプレッドシート転記【確定】

**転記単位：** 商品1行につき1レコード（1会計で3商品なら3行が追記される）

**会計番号：** すべてのレコードに会計番号を付与する。同一会計の行は同じ会計番号を持つため、スプレッドシート側で会計番号によるグルーピング・フィルタを行えば、会計単位での確認・集計も可能となる。

- 採番規則：`YYYYMMDD-{端末コード}連番3桁`（例：`20260723-A014`）。連番は端末ごと・日付ごとに 001 にリセットする（詳細は 5.4）
- 会計番号は取消処理（FR-15）における元会計の特定キーとしても使用する

**転記項目**

| 列 | 項目 | 内容例 | 備考 |
| --- | --- | --- | --- |
| A | 日付 | 2026/07/23 | 会計確定日 |
| B | 時刻 | 14:32 | 集計・分析用に付与（要件外だが推奨） |
| C | 会計番号 | 20260723-A014 | 端末コードを含む一意の会計番号。同一会計の行を紐づけるキー |
| D | 端末コード | A | 会計を行った端末の識別子（端末別集計用） |
| E | 商品名 | からあげ串 | 確定時点の商品名を保持 |
| F | 金額 | 500 | 割引適用後の1点あたり単価 |
| G | 個数 | 2 | |
| H | 小計 | 1000 | 金額 × 個数 |
| I | 割引額 | 50 | 1点あたりの割引額 |
| J | 備考 | イベント割 | 会計単位の備考（全行に同じ値を転記） |

> ご指定の必須項目「日付・商品名・金額・個数・備考」に加え、会計単位での確認のため会計番号（C列）、複数台運用のため端末コード（D列）を必須項目として追加する。時刻・小計・割引額は集計精度を高めるための付帯項目とする。

**要件**

- 会計確定後、伝票は自動的にクリアされ、次の会計を即座に開始できる状態になる
- 通信エラー等で転記に失敗した場合、会計自体は成立させ、未送信データとして端末内に保持する。通信回復時に自動再送する
- 未送信データが存在する場合、画面上部に件数バッジを表示する

### 6.10 FR-15 会計の取消（推奨機能）

- 当日の会計履歴から対象の会計を選択し、取消を実行できる
- 取消時はスプレッドシートに個数をマイナスにしたレコードを追記する（元の行は削除しない）
- 備考欄に「取消（元会計番号）」を自動で記載する

## 7. 画面要件

### 7.1 画面一覧

| ID | 画面名 | 概要 |
| --- | --- | --- |
| SC-01 | 会計画面 | メイン画面。商品追加・伝票表示・精算 |
| SC-02 | 精算モーダル | 預かり金入力・釣銭表示・会計確定 |
| SC-03 | 商品マスタ管理画面 | 商品の一覧・追加・編集・削除 |
| SC-04 | カテゴリ管理画面 | カテゴリの一覧・追加・編集・削除 |

## 8. データ要件

専用データベースを持たないため、データはすべて Google スプレッドシートの**タブ（シート）と列**で表現する。1つのスプレッドシートファイル内に、以下のタブを設ける。

### 8.1 タブ構成

| タブ名 | 役割 | 更新方法 |
| --- | --- | --- |
| `商品マスタ` | 販売する商品の一覧 | 商品管理画面から編集（GAS 経由） |
| `カテゴリ` | カテゴリの一覧 | カテゴリ管理画面から編集（GAS 経由） |
| `端末` | 利用端末の登録情報 | 端末の初回登録時に追記 |
| `売上ログ_YYYYMM` | 月ごとの売上明細（1商品1行） | 会計確定時に GAS が追記（追記専用） |

> 売上ログは月ごとにタブを分ける。1タブあたりの行数増大による動作低下を避けるため。当月のタブが存在しない場合は GAS が自動生成する。

### 8.2 各タブの列設計

**`商品マスタ` タブ**

| 列 | 項目 | 型 | 備考 |
| --- | --- | --- | --- |
| A | No. | 整数 | 一意。画面上は①②③…の丸数字で表示 |
| B | 商品名 | 文字列 | 30文字以内 |
| C | 金額 | 整数 | 税込・0以上 |
| D | カテゴリ名 | 文字列 | `カテゴリ` タブのカテゴリ名と対応 |
| E | 表示順 | 整数 | 未指定時は No. 順 |
| F | 販売状態 | 文字列 | `有効` / `無効` |

**`カテゴリ` タブ**

| 列 | 項目 | 型 | 備考 |
| --- | --- | --- | --- |
| A | カテゴリ名 | 文字列 | 一意 |
| B | 表示順 | 整数 | 会計画面のタブ並び順 |
| C | 表示色 | 文字列 | 色コード等（任意） |

**`端末` タブ**

| 列 | 項目 | 型 | 備考 |
| --- | --- | --- | --- |
| A | 端末コード | 文字列 | A・B・C… または任意名称。一意 |
| B | 端末名 | 文字列 | 「レジ1」等の表示用名称 |
| C | 登録日時 | 日時 | 初回登録日時 |
| D | 状態 | 文字列 | `有効` / `無効`（紛失時に無効化） |

**`売上ログ_YYYYMM` タブ（会計確定時に1商品1行で追記）**

| 列 | 項目 | 内容例 | 備考 |
| --- | --- | --- | --- |
| A | 日付 | 2026/07/23 | 会計確定日 |
| B | 時刻 | 14:32 | 集計・分析用 |
| C | 会計番号 | 20260723-A014 | 端末コードを含む一意の会計番号。同一会計の行を紐づけるキー |
| D | 端末コード | A | 会計を行った端末（端末別集計用） |
| E | 商品名 | からあげ串 | 確定時点の商品名 |
| F | 金額 | 500 | 割引適用後の1点あたり単価 |
| G | 個数 | 2 | |
| H | 小計 | 1000 | 金額 × 個数 |
| I | 割引額 | 50 | 1点あたりの割引額 |
| J | 備考 | イベント割 | 会計単位の備考（同一会計の全行に同じ値） |

> 会計単位の情報（合計金額・預かり金・釣銭）は、売上ログを会計番号でグルーピングすれば算出できるため、専用タブは設けない。必要に応じて集計用タブを別途追加する。

### 8.3 端末側キャッシュ（IndexedDB）

正データはスプレッドシートに置くが、オフライン動作と応答速度のため、各端末は以下を IndexedDB に保持する。

| 保持データ | 内容 | 更新契機 |
| --- | --- | --- |
| マスタキャッシュ | `商品マスタ`・`カテゴリ` の複製 | 起動時・オンライン復帰時に GAS から再取得 |
| 未送信キュー | 確定済みだが未送信の売上明細 | 会計確定時に追加、送信成功時に削除 |
| 入力中伝票 | 会計途中の伝票状態 | 操作のたびに保存（再読み込み時の復元用） |

### 8.4 データ保持

- スプレッドシート上の正データは無期限保持する
- 端末側の IndexedDB キャッシュは、未送信キューを除きいつ破棄されても正データから復元できる（未送信キューのみ消失させてはならない）

## 9. 非機能要件

| 区分 | ID | 要件 |
| --- | --- | --- |
| 性能 | NF-01 | 商品追加・個数変更の画面反映は 0.3 秒以内 |
| 性能 | NF-02 | 会計確定の操作完了は 1 秒以内（スプレッドシート転記の完了を待たない） |
| 可用性 | NF-03 | 通信断時も注文入力・精算・会計確定を継続できる（オフライン対応・**必須**） |
| 可用性 | NF-04 | 端末のスリープ・ブラウザ再読み込み後も、入力中の伝票を復元できる |
| セキュリティ | NF-05 | ログイン認証（店舗共通アカウントまたは PIN コード）を必須とする |
| セキュリティ | NF-06 | 通信はすべて HTTPS とする |
| セキュリティ | NF-07 | 商品マスタの編集・削除、会計取消の操作ログを記録する |
| 保守性 | NF-08 | 商品・カテゴリの追加変更は、開発者を介さず店舗側の操作のみで完結できる |
| 運用 | NF-09 | 端末を紛失した場合に、管理者側からアクセスを無効化できる |

### 9.1 オフライン動作要件【確定】

屋外イベントや電波状況の悪い環境での利用を想定し、**通信が完全に切れた状態でも会計業務を止めない**ことを必須要件とする。

| 項目 | 要件 |
| --- | --- |
| 動作範囲 | 商品選択・伝票操作・割引・合計算出・預かり金入力・釣銭算出・会計確定のすべてがオフラインで実行できる |
| マスタデータ | 商品・カテゴリのマスタは端末内（IndexedDB）にキャッシュし、オフライン時はキャッシュを参照する |
| アプリ本体 | Service Worker によりアプリ本体（HTML/CSS/JS）を端末にキャッシュし、圏外でも起動できる |
| 会計データ | 会計確定時は端末内に保存し、成立扱いとする。スプレッドシートへの転記は「未送信キュー」に積む |
| 会計番号 | オフライン中も端末内で採番する。端末コードを含むため（5.4）、複数端末が同時にオフラインでも会計番号は重複しない |
| 同期 | 通信回復を検知し、未送信キューを古い順に自動送信する。送信成功したデータには同期済フラグを立てる |
| 可視化 | 画面上部に接続状態インジケータと未送信件数バッジを常時表示する |
| 手動同期 | 設定画面から手動での再送信を実行できる |
| データ保全 | 未送信データが残った状態でアプリを閉じても消失しない。未送信データがある状態でのログアウトは警告を表示する |
| 上限 | 未送信データは最大1,000件まで保持する。超過時は管理者へ警告を表示する |

> マスタの編集（商品追加・価格変更）はオンライン時のみ可能とする。オフライン中の編集を許可すると端末間で不整合が発生するため。
